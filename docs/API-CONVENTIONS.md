# API Conventions

## Base
- Base URL: `https://api.<platform>.com/api/v1`.
- **School (tenant) APIs:** `/api/v1/**`. The school is taken **only from the authenticated session**, never from the URL, body or a header.
- **Super admin APIs:** `/api/v1/platform/**`. These need a platform session + TOTP.
  - `/platform/schools/**`: manage schools, domains and school users.
  - `/platform/overview/**`: cross-school figures, reports and exports (all schools at once).
  - `POST /platform/active-school { schoolId }` sets the school the super admin is working in. After that, **all normal school APIs** (`/api/v1/**`)
    work for the super admin with full permissions in that school. `DELETE /platform/active-school` returns to the overview.
- **Public website APIs:** `/api/v1/public/**`, no authentication. The school is resolved from `X-School-Host`, which only the Next.js server sets after
  host lookup. The request is signed with a shared secret (`X-Public-Signature`) so browsers cannot spoof another school.
- Sign-in: `POST /api/v1/auth/login { schoolCode, username, password }`. Platform sign-in: `POST /api/v1/platform/auth/login { email, password, totp }`.
- JSON only, `camelCase` fields. Dates use ISO `YYYY-MM-DD`; timestamps use ISO-8601 UTC.
- **Money is sent as a string** (`"3500.00"`) to avoid JS float errors. The frontend formats it with `Intl.NumberFormat('en-PK')`.
- OpenAPI 3 is generated by springdoc at `/v3/api-docs` (disabled in production or behind auth). Frontend types are generated from it.

## Resources and verbs
```
GET    /students?classId=&sectionId=&status=&q=&page=&size=&sort=name,asc
GET    /students/{id}
POST   /students                       create
PATCH  /students/{id}                  partial update (send only changed fields)
POST   /students/{id}/withdraw         state transitions are explicit action endpoints
POST   /students/{id}/move
POST   /fees/payments                  requires Idempotency-Key
POST   /fees/payments/{id}/reverse     body: { reason }
POST   /exams/{id}/classes/{classId}/publish
```
- There are no `DELETE` endpoints for financial or historical records. Master data uses `POST /{id}/deactivate`.
  `DELETE` is allowed only for unused master data, and it returns `409 IN_USE` with usage details otherwise (FR 9.7).

## Headers
| Header | Direction | Purpose |
|---|---|---|
| `Cookie: SMS_SESSION` | req | HTTP-only session cookie |
| `X-XSRF-TOKEN` | req | CSRF token on every state-changing request (incl. login). Get it from `GET /api/v1/auth/csrf` (JSON `token`); the matching `XSRF-TOKEN` cookie is HttpOnly and sent automatically. Refetch after sign-out or a 403 |
| `X-Academic-Year` | req | Selected academic year ID; defaults to the current year |
| `Idempotency-Key` | req | UUID, required on payment, bill-run, message-send and voucher-batch endpoints |
| `X-Request-Id` | both | Correlation ID |
| `X-Step-Up-Token` | req | Required for sensitive endpoints after OTP verification |

## Pagination
Request: `page` (0-based), `size` (default 25, max 200), `sort`.
Response:
```json
{ "items": [ ... ], "page": 0, "size": 25, "totalItems": 807, "totalPages": 33 }
```

## Errors: RFC 9457 Problem Details
```json
{
  "type": "https://api.<platform>.com/problems/validation",
  "title": "Validation failed",
  "status": 422,
  "code": "VALIDATION_FAILED",
  "detail": "One or more fields are invalid",
  "errors": [ { "field": "marks[3].obtained", "code": "MAX_EXCEEDED", "message": "112 exceeds maximum 100" } ],
  "requestId": "..."
}
```
| Status | code examples |
|---|---|
| 400 | MALFORMED_REQUEST |
| 401 | UNAUTHENTICATED, SESSION_EXPIRED |
| 403 | FORBIDDEN, STEP_UP_REQUIRED, OUT_OF_SCOPE |
| 404 | NOT_FOUND (also used for out-of-scope and other-school records, to avoid leaking that they exist) |
| 423 | SCHOOL_SUSPENDED |
| 409 | CONFLICT_VERSION, IN_USE, DUPLICATE_SUSPECTED, YEAR_CLOSED, ALREADY_BILLED |
| 422 | VALIDATION_FAILED, BUSINESS_RULE (for example DISCOUNT_NEEDS_APPROVAL) |
| 429 | RATE_LIMITED (login, password reset, public forms) |

Messages are returned in English. The frontend may map `code` to friendlier English text.

## Concurrency
Mutable resources return `version`. `PATCH` must send `version`, and a mismatch returns `409 CONFLICT_VERSION`.

## Async jobs
Long operations (bill runs, voucher PDFs, bulk SMS, report exports) return `202 Accepted` with `{ "jobId": ... }`.
Clients poll `GET /jobs/{id}` and receive `status`, `progress`, `resultFileUrl` and `errors`.

## Files
- Upload: `POST /files` multipart, which returns `{ fileId }`. The file is then linked to its owner in the owner's create/update request.
- Download: `GET /files/{id}/url` returns a short-lived presigned URL after a permission check.

## Versioning
Breaking changes need `/api/v2`. Additive changes are allowed in v1.
